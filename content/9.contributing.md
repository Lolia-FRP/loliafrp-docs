## 文档仓库

本文档网站的所有内容都在[公开仓库](https://github.com/Lolia-FRP/loliafrp-docs)，您可以使用 [Git](https://git-scm.com) 与 [GitHub](https://github.com) 完成对此文档的贡献。本文假设您对 Git 和 GitHub 有一定的了解，并有一定的操作经验。

## 文档规范

- **文件与目录**用数字前缀 `1.xxx` `2.xxx` 控制侧边栏顺序
- **每个文件夹**配一个 `.navigation.yml`，写明 `title` 与可选的 `navigation.icon`
- **每页的 frontmatter** 必须有 `title` 和 `description`
- **图标**取自 [Lucide](https://lucide.dev/icons/)，写成 `i-lucide-git-pull-request` 的形式
- **图片**放在 `public/` 下，目录结构与文档一一对应，去掉数字前缀。例如 `content/4.client/1.gui/1.loliafrpclient/2.Windows.md` 对应 `public/client/gui/loliafrpclient/Windows/`

推荐在一级菜单和二级菜单上都添加icon，深入的层级则不添加。如果您不确定选择什么，可以留空。

:::note
`description` 会被添加至 [llms.txt](https://docs.lolia.link/llms.txt)中，Lolia Intelligence 会根据描述判断对应文档的内容，因此请保持描述清晰、有意义
:::

## 提交 Pull Request

1. 在 GitHub 网页端 Fork 仓库

   ![Create a new fork 页面，确认 Owner 与仓库名](/contributing/create_new_fork.png)

2. Clone 您的 Fork 到本地：

   ```bash
   git clone https://github.com/<您的用户名>/loliafrp-docs.git
   cd loliafrp-docs
   ```

3. 新建分支后修改 `content/` 下对应的文件：

   ```bash
   git checkout -b docs/fix-typo
   ```

4. 提交并推送到自己的仓库，然后回到 GitHub 发起 Pull Request，简述您的改动。

## 本地预览

文档基于 Nuxt Content + Docus 构建，本地预览需要 [Bun](https://bun.sh)：

```bash
bun install
bun dev
```

如果Node版本过高，可以尝试使用
```bash
npm install --no-package-lock
npm run dev
```

打开终端里输出的地址即可，您的改动会自动热更新并显示。
