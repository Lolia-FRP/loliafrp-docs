## 确认架构

先看路由器的 CPU 架构：

```sh
uname -m
```

| `uname -m` 输出 | 选择发布包 |
| --- | --- |
| `x86_64` | `linux_amd64` |
| `i386` / `i686` | `linux_386` |
| `aarch64` | `linux_arm64` |
| `armv7l` | `linux_arm` |
| `mips` / `mipsel` / `mips64` | 发布包中没有对应版本，需要自行编译，见[构建与发布](/references/lolia-frpc/release) |

发布包中的 `linux_arm` 按 `GOARM=7` 构建（构建脚本没有设置 `GOARM`，使用 Go 的默认值），`armv5`、`armv6` 的老路由器需要自行编译时指定 `GOARM=5` 或 `GOARM=6`。

## 源码编译

发布包中没有 mips、mipsel、mips64，`armv5`、`armv6` 的老路由器也无法直接使用按 `GOARM=7` 构建的包，这两种情况需要自行编译。

构建命令、构建标签与交叉编译变量见[构建与发布](/references/lolia-frpc/release)。编译到路由器时注意：

- `armv5`、`armv6` 需要加 `GOARM=5` 或 `GOARM=6`；
- mips 系列需要加 `GOMIPS=softfloat`（默认的 `hardfloat` 在无 FPU 的路由器上无法运行，mips64 用 `GOMIPS64`）。

## 上传文件

在电脑上解压后，把 `frpc` 传到路由器的 `/usr/bin`（`frps` 不需要）：

```sh
scp frpc root@192.168.1.1:/usr/bin/frpc
```

然后登录路由器，补上执行权限：

```sh
chmod +x /usr/bin/frpc
frpc -v
```

输出的版本应与发布页的 v 标签一致。

先手动运行一次，确认 token 与网络都没问题，再配置服务（按 `Ctrl+C` 退出）：

```sh
frpc -t 隧道id:节点TOKEN
```

## 编写 init 脚本

新建 `/etc/init.d/loliafrp`：

```sh
#!/bin/sh /etc/rc.common

START=99
STOP=10
USE_PROCD=1

PROG=/usr/bin/frpc
WORKDIR=/etc/loliafrp
FRPC_ARGS="-t 隧道id:节点TOKEN"

start_service() {
	mkdir -p "$WORKDIR"
	procd_open_instance
	procd_set_param command /bin/sh -c "cd $WORKDIR && exec $PROG $FRPC_ARGS"
	procd_set_param respawn
	procd_set_param stdout 1
	procd_set_param stderr 1
	procd_close_instance
}
```

| 配置 | 说明 |
| --- | --- |
| `START=99` | 启动顺序，在大多数系统服务之后 |
| `USE_PROCD=1` | 交给 procd 托管，退出后自动拉起 |
| `PROG` | `frpc` 的路径 |
| `WORKDIR` | 进程工作目录，AutoTLS 的 `./.autotls-cache` 相对它解析 |
| `FRPC_ARGS` | 传给 frpc 的参数，多个隧道写成多个 `-t` |
| `respawn` | 进程退出后自动重启 |
| `stdout` / `stderr` | 把日志交给 logd，用 `logread` 查看 |

多个隧道：

```sh
FRPC_ARGS="-t 隧道1:节点TOKEN1 -t 隧道2:节点TOKEN2"
```

使用配置文件启动时改成 `FRPC_ARGS="-c $WORKDIR/frpc.toml"`，并把配置文件放在同一个目录下。

赋予执行权限：

```sh
chmod 755 /etc/init.d/loliafrp
```

## 启用并启动

```sh
/etc/init.d/loliafrp enable
/etc/init.d/loliafrp start
```

`enable` 会创建开机启动链接，`start` 立即启动。查看状态：

```sh
/etc/init.d/loliafrp status
```

## 查看日志

procd 会把 frpc 的标准输出交给 logd：

```sh
logread -e loliafrp
```

持续跟踪：

```sh
logread -f
```

## 常用操作

| 操作 | 命令 |
| --- | --- |
| 启动 | `/etc/init.d/loliafrp start` |
| 停止 | `/etc/init.d/loliafrp stop` |
| 重启 | `/etc/init.d/loliafrp restart` |
| 查看状态 | `/etc/init.d/loliafrp status` |
| 启用开机自启 | `/etc/init.d/loliafrp enable` |
| 禁用开机自启 | `/etc/init.d/loliafrp disable` |

## 更新客户端

```sh
/etc/init.d/loliafrp stop
scp frpc root@192.168.1.1:/usr/bin/frpc
chmod +x /usr/bin/frpc
/etc/init.d/loliafrp start
```

`WORKDIR` 下的 `.autotls-cache` 目录不要删除，否则会重新申请证书。

## 空间不足时压缩二进制

发布包里的 `frpc` 约 18 MB，闪存较小的路由器可能放不下。先看剩余空间：

```sh
df -h /
```

空间不够时可以用 UPX 压缩。在**电脑上**操作即可，不需要在路由器上安装 UPX：

1. 从 [UPX Releases](https://github.com/upx/upx/releases) 下载对应电脑系统的版本并解压。
2. 把 `frpc` 和 `upx` 放在同一个目录，执行：

   ```sh
   upx --best --lzma frpc
   ```

3. 校验结果：

   ```sh
   ls -lh frpc
   upx -t frpc
   ```

实测 arm 版从 16.8 MB 压到 4.3 MB，mips 版从 18.9 MB 压到 4.2 MB（约四分之一，UPX 5.3.0）。确认无误后再上传到路由器。

需要还原原始文件时：

```sh
upx -d frpc
```

:::caution
压缩后的程序启动时需要额外一点内存用于解压，内存很小的路由器（如 64 MB）建议在低峰时段试运行，确认稳定后再启用开机自启。如果压缩后的程序无法运行，用 `upx -d` 还原。
:::

### 其他省空间的方法

- 发布包里的 `frps` 不需要上传，只保留 `frpc`。
- 把 `frpc` 放到 U 盘或 extroot 分区，避免占用 `/overlay`。
- 用[源码编译](/references/lolia-frpc/release)时带上 `noweb` 标签，去掉内置 Web 面板资源。

## 注意事项

- 快捷启动的配置只在 frpc 启动时拉取一次，在面板修改隧道配置后需要 `/etc/init.d/loliafrp restart` 才会生效。
- 同一条隧道只能有一个实例在线，注册服务后不要再手动运行 `frpc -t ...` 启动同一条隧道。
- 首次登录失败时 frpc 会退出（`loginFailExit` 默认开启），由 procd 的 `respawn` 重新拉起；token 失效时会反复重试，`logread -e loliafrp` 中可以看到具体错误。
- 脚本中的 token 会出现在 `/etc/init.d/loliafrp`、`ps` 与 `logread` 里。可以把脚本权限设为 `700`，或改用 `-c` 配置文件启动并限制配置文件的读取权限。
