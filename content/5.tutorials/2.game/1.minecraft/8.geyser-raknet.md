title: 旧版 Geyser（RakNet）
description: 旧版 Geyser 的 RakNet 传输配置
---

:::caution
旧版 Geyser 只有 RakNet 传输。新版 Geyser 默认已经转到 NetherNet，配置方式见 [Geyser 互通服](/tutorials/game/minecraft/geysermc)。
:::

由于 Bedrock Edition 的更新比较频繁且版本兼容性非常差，您应当很快就不再使用本教程。

故此处仅做简略的介绍，搭配机器翻译对原始配置文件注释翻译，然后跟随本教程创建隧道并修改对应参数然后启动即可。请善用ctrl+f。

插件版和独立版配置大同小异，仅在 Java 连接本地服务器部分有些许差异。

## 二、创建隧道

| 字段 | 填写 |
| --- | --- |
| 隧道类型 | `UDP` |
| 本地 IP | `127.0.0.1` |
| 本地端口 | `19132`，等下需要改 |
| 远程端口 | 留空自动生成 |

创建完成之后找到形如 `cn-frp-1.qwq.fan:14514` 的连接地址，其中冒号的前半部分是域名，后半部分是端口。

然后在隧道的配置界面设置本地端口为远程端口，如 `14514`。

## 三、修改 Geyser 配置

打开 `config.yml`：

```yaml
bedrock:
  # 把19132改成刚才的远程端口。如 14514
  port: 19132
```

## 四、回源 Java 的真实 IP

对于独立版Geyser：如果 Java 版服务器启用了PROXY protocol，那么需要打开这个开关。

Geyser 连 Java 服务端时会把访客地址换成自己的地址。旧版的开关在 `remote` 段：

```yaml
remote:
  use-proxy-protocol: true
```

插件版也需要设置。

## 五、常见问题

### 服务器列表里看不到 MOTD

远程端口与本地端口不一致，或者 UDP 隧道没有启动。按第三节设置 `broadcast-port`，或把两端端口改成同一个。

### 开启了PROXY protocol无法连接到服务器

如果您在（例如：Velocity）日志中看到了`Caused by: java.lang.RuntimeException: HAProxy support is not enabled`等日志，说明服务端没有启用PROXY protocol，但Geyser错误的打开了。此时考虑打开Velocity的 PROXY protocol 开关或关闭 Geyser 的 PROXY protocol。

特别的，对于插件版且启用了direct connection的Geyser，无需开启PROXY protocol也是可以正常连接的；另外的，无法看见连接的端口号是意料之内的正常行为。
