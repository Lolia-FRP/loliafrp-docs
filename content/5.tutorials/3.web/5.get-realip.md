:::warning
承载 HTTPS 的站点只能用 `PROXY protocol`：TLS 由 frps 直接透传、不做解析，`X-Forwarded-For` 不会被追加。
:::

## NGINX

Nginx 用 realip 模块把访客 IP 覆盖到 `$remote_addr`，两种方案的区别只在于 `real_ip_header`。

`HTTP` 隧道可读取 `X-Forwarded-For`，面板不需要任何配置，frpc 会自动把访客 IP 追加到该请求头末尾：

```nginx
server {
    listen 80;

    # frpc 在本地运行写 127.0.0.0/8，不同机时写 frpc 的内网地址或CIDR段
    set_real_ip_from 127.0.0.0/8;
    real_ip_header X-Forwarded-For;

    # 原有内容不变，此时 $remote_addr 已是访客 IP
}
```

:::warning
`X-Forwarded-For` 的前半部分完全由访客控制。realip 会从右往左取第一个不在 `set_real_ip_from` 里的地址，所以必须把 `set_real_ip_from` 限定为 frpc 的地址，否则访客可以直接伪造来源 IP。
:::

`HTTPS`、`TCP`、`UDP` 隧道开启 `PROXY protocol`：

```nginx
server {
    listen 80 proxy_protocol;

    set_real_ip_from 127.0.0.0/8;
    real_ip_header proxy_protocol;

    # 原有内容不变
}
```

:::caution
`listen` 上开启 `proxy_protocol` 后，该端口（包括其它配置文件里的同一端口）的**所有**连接都会按 PROXY protocol 解析，浏览器无法直接访问该端口。
:::

## Apache

要求 Apache `>= 2.4.30` 并启用 `mod_remoteip`（Debian/Ubuntu 可执行 `a2enmod remoteip`）。

`HTTP` 隧道读取 `X-Forwarded-For`：

```apache
<VirtualHost *:80>
    ServerName example.com

    RemoteIPHeader X-Forwarded-For
    RemoteIPInternalProxy 127.0.0.0/8
</VirtualHost>
```

`HTTPS`、`TCP`、`UDP` 隧道开启 `PROXY protocol`：

```apache
<VirtualHost *:80>
    ServerName example.com

    RemoteIPProxyProtocol On
</VirtualHost>

<VirtualHost *:443>
    ServerName example.com
    SSLEngine on
    SSLCertificateFile      /path/to/fullchain.pem
    SSLCertificateKeyFile   /path/to/privkey.pem

    RemoteIPProxyProtocol On
</VirtualHost>
```

:::warning
`RemoteIPProxyProtocol` 按 VirtualHost 生效，80 和 443 要各写一遍，漏写的那个端口仍会把访客地址记成 `127.0.0.1`。
:::

配置完成后 `%a` 即为访客 IP。

## 雷池WAF

:::tip
雷池WAF的逐应用配置的功能要求商业版，故使用社区版时为多个网站多个端口分别配置PROXY protocol可能需要一些小技巧，此处不赘述。
:::

如果您第一次接触雷池WAF，可以先阅读 [雷池 WAF 帮助文档](https://help.waf-ce.chaitin.cn/)。

此处以雷池9.4.3为例。我们假设您已经安装了雷池。

![寻找高级配置](/tutorials/web/safeline-find-advanced-settings.png)

在雷池的防护应用-高级配置中配置源IP获取方式为 `从 PROXY Protocol 中获取`，然后白名单设置为运行Lolia FRP的机器，或如果您确信您的雷池被防火墙完整防护，只有frpc可以直接连接，那么也可以设置为0.0.0.0/0。

此处由于示例机器和frpc均运行在虚拟机内，因此直接配置了 `0.0.0.0/0`

![PROXY protocol设置](/tutorials/web/safeline-proxyprotocol-settings.png)

:::tip
由于前述原因，您可能无法同时使用IPv6进行直接连接，源站调试时您可以绕过雷池访问源站。
:::

## 用 X-Forwarded-For 拿到的还是 127.0.0.1

1. 确认隧道类型是 `HTTP`，`X-Forwarded-For` 对 `TCP`、`UDP`、`HTTPS`隧道无效
2. 确认 `set_real_ip_from`（Nginx）或 `RemoteIPInternalProxy`（Apache）写的是 frpc 的地址
3. 确认读的是 `$remote_addr` / `%a`，而不是自己另外拼的变量
