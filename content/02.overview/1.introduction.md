## 为什么需要内网穿透？

:::tip
此部分不是面向计算机专业的用户，我们已知有许多不严谨的地方并不计划修正。
:::

此处我们假设 Alice 和 Bob 各有一台电脑，Bob 想让 Alice 看自己的网页或者一起联机玩游戏或者做些其他什么，要怎么办呢？

聪明的你已经知道了，Bob 的服务要监听一个端口，然后 Alice 连进来，而监听端口本质上就是接受数据包传入，仅此而已，那么我们来深入的剖析一个连接是如何建立的。

首先 Alice 需要找到 Bob，而数据包就需要沿着路上的路由器走到 Bob 的路由器。

那么转发到 Bob 的计算机上后，需要有一个服务接收这个数据包，我们约定俗成的叫监听端口，也就是 frpc 需要设置的本地端口，也就是可以从这个端口接收和发送数据。

Bob 接收到数据包后处理，然后通常沿原路返回数据包给 Alice。这就是连接建立的本质过程。

理解之后我们再来看为什么会需要内网穿透，前面说我们已经知道 Bob 的 IP 地址，但现实中并不是所有设备都有一个 IP 地址，例如 Bob 和 Cathy 可能连在一个路由器上，而一个路由器就会对应 Bob 和 Cathy，但路由器有可能不受您的控制，它并不知道转发给 Bob 还是 Cathy，那数据包在路由器不知道要发给谁就只能丢掉了。

而我们思考了一个方法，那么就是提前找一个中间人（frps），告诉中间人收到什么内容就发给 Bob，也就是让 Alice 访问中间人（也就是远程地址）的一个端口（也就是远程端口），中间人知道这个端口是 Bob 的，那么 Alice 给中间人发消息，Bob 就能收到了，这就是 frp 的原理。

聪明的你一定注意到了，frpc 必须先连接到 frps，才能建立数据转发的通道，因此如果 frpc 不在线，frps 是无法转发的，表现为访客无法连接到您的服务。

:::tip
frp 不是云服务器，您的所有服务都运行在您的电脑上，因此提供服务的电脑并不能关机，否则服务就会断开。
:::

同样的，如果您本地的服务不在线，frpc 无法连接到您本地的服务时，也表现访客为无法连接到您的服务。

## 它能做什么

暴露你希望暴露的服务到公网。

常见的服务例如：

- 各类游戏服务器的房主，如 Minecraft Server 等。
- 远程桌面，如 Remote Desktop Service，SSH，VNC Server 等。
- 网页，如 WordPress 等。

## 我要怎么暴露服务到公网？

首先，需要创建一个隧道，然后通过在要开放的服务上安装一个frpc并让它跑起来，然后frps就会把服务暴露在外，那么用户连接到frps的时候，连接到的就是您的本地服务了。

## 选择的隧道类型

通常这取决于您的服务和应用要求使用哪种隧道。常见的列表如下，具体请参考您的服务的文档。

| 应用 | 类型 |
| --- | --- |
| `Minecraft Java Edition` | `TCP` |
| `Minecraft Bedrock Edition` | `UDP` |
| `Remote Desktop Service` | `TCP+UDP` |
| `SSH` | `TCP` |
| `Nginx, Apache` | `HTTP(S)` |
| `各类路由器，NAS管理页面` | `HTTP(S)` |

HTTP(S)隧道基于TCP，但对Web服务进行了特殊优化。

Lolia Frp不允许使用TCP隧道进行Web服务穿透。
